# GrowBot on Andrew's calibrated Pico body

Integration note for Brit, 23 September 2026. This is the existing working approach, not a new firmware release or a claim that the controller disconnect is solved.

**Versions and page.** The phone uses the live GrowBot app at [growbot.dev/](https://growbot.dev/). The controller is a Pico 2 W on a Waveshare Pico Servo Driver with MicroPython 1.28.0. The last verified installed firmware reports `owlbot-pico-7.15` (22 September). Its base source is the [published OwlBot Pico 7.14 controller](https://github.com/Aaronminer1/owlbot/tree/main/firmware/pico); the installed 7.15 changes are a faster GrowBot-only stock walk (saved 1,600 µs/s plan interpreted at 2,000 µs/s) and retained commanded positions at gait startup. The installed 7.15 delta changed `stock_body.py`, `servo_channels.py` and the firmware version label in `main.py`; it has not yet been published as source. The public repository is still a 7.14 source snapshot, so do not identify it as a byte-for-byte copy of the installed board.

**How commands reach the body.** GrowBot's ordinary `walk` action streams virtual two-leg `pose` frames (`lr` values) through its existing relay. `main.py` calls `apply_pose(l,r)`, and `stock_body.py` recognizes the sustained alternating support pattern, then runs the saved four-leg plus slide gait locally from `named_walk.json` through `servo_channels.py`. Neutral or a stopped stream ends that local gait. A pose or relay ACK is not distance or servo-position feedback.

Turns and head motions use GrowBot's existing saved-gesture `act` packet, with `mode:"replace"` and eight `l/r/ms` frames. `stock_commands.py` recognizes **only an exact frame match** before passing opcodes 1–2 to the taught `named_turn.py` sequence (including return to calibrated `Closed`) and opcodes 3–7 to the paced `pico_head.py` pan/tilt controller. The firmware also accepts `routine.name` aliases for `turn left/right` and `spin left/right`, but GrowBot's shipped phone app does not currently send `routine` packets. The working phone path for these turns and head moves is `act`. The normal unlabeled `pose` stream is never interpreted as a turn. Head pan/tilt extent is 60% of each calibrated range, with a 150 µs/s head speed limit; the installed configuration keeps head support enabled. This leaves the head held after a completed command.

**Saved gestures.** The live body configuration contains `wiggle` plus these seven exact names and frame sequences. Each tuple below is `(l = r, ms)`; both `l` and `r` must equal the first number. The decoder validates the full sequence, including durations. These are command markers, not literal requested leg poses:

| Name | Opcode | Eight frames |
| --- | ---: | --- |

| `turn right` | 2 | `(87,137) (93,149) (88,163) (92,181) (105,193) (92,197) (86,2000) (90,2000)` |
| `look left` | 3 | `(87,137) (93,149) (88,1500) (93,1500) (104,1500) (92,1500) (86,2000) (90,2000)` |
| `look right` | 4 | `(87,137) (93,149) (88,1500) (94,1500) (103,1500) (92,1500) (86,2000) (90,2000)` |
| `look up` | 5 | `(87,137) (93,149) (88,163) (95,181) (102,193) (92,197) (86,2000) (90,2000)` |

The firmware's [`frames(op)` definition](https://github.com/Aaronminer1/owlbot/blob/main/firmware/pico/stock_commands.py) is the canonical generator. The live phone configuration was inspected read-only and matched these seven definitions. GrowBot's [body guide](https://growbot.dev/body-docs.html) describes the underlying `pose`, `act`, `routine` and `stop` wire envelopes.

**Local files and setup.** On the Pico, `main.py` is the boot entrypoint; `relay_chip.py` is a source mirror. The Python modules named above plus `stock_fanout.py`, `shared_body.py`, `PicoRobotics.py`, `dog_engine.py` and `gimbal_engine.py` implement this mapping. Private runtime files are `servo_channels.json` (eight channel assignments, endpoint labels and pulse limits), `named_walk.json` (taught gait and binding snapshots), `dog_cal.json` / `dog_gait.json` (legacy body calibration), `gaze_cal.json` (head ports and limits), and `stock_commands.json` (enable, observed turn direction, pan inversion, turn fraction and head hold). `secrets.py` holds Wi-Fi and relay details; keep it and any control token or pairing code private. GrowBot's saved gesture definitions and creature data live in the phone's local body/creature configuration; do not publish that whole store to share the seven frame sequences.

For a clean setup, start from the [public disabled `stock_commands.example.json`](https://github.com/Aaronminer1/owlbot/blob/main/firmware/pico/stock_commands.example.json). Calibrate the actual servo channels, save a ten-step alternating diagonal walk with its channel bindings, observe which taught turn pattern physically points left, set `pattern_a_direction` from that observation, then set the correct pan inversion, desired bounded `turn_fraction` and head hold. The tested robot uses a 0.60 turn fraction, inverted pan semantics and head hold. Enable saved commands only after those mappings are known. Export each exact eight-frame sequence above into the seven corresponding GrowBot saved gestures. The source README has the setup and calibration constraints; no passwords, pairing values or creature memories are needed for the integration.

**Current limits.** GrowBot's relay has no independent client authentication: possession of the pairing code is enough to attach as a controller or body. This firmware derives a short code from the Pico ID; keep the code private and do not treat pairing as proof of the peer's identity. During the earlier connection failure, the phone reopened its socket but Pico replies did not return in the observation window. The app also reported a completed walk after the robot had physically stopped. Neither issue is resolved by this integration note. A future face-tracking experiment should start with the body stationary and use the calibrated, paced head controller before attempting tracking during walking.
